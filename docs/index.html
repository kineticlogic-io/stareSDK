Elite Command Design System

@kineticlogic/staresdk is the React component library, theming and design-token set behind OpenStare and OpenTrack. Every example on this page is the real component from this release, running live. Use the theme button in the header to see each one in dark and light.

Overview#

The package ships the components, ThemeProvider/useTheme (dark and light), the chromeTheme.ts token set, and optional map, graph, chart and code-editor views. Components take their data as props. Routing, data fetching and app state stay in your app.

Usage#

Import the stylesheet once at your application's entry point, wrap your tree in ThemeProvider (and ToastProvider if you use Toast/useToast), then import components by name:

import '@kineticlogic/staresdk/styles.css'
import { ThemeProvider, ToastProvider, Button, Modal, useTheme } from '@kineticlogic/staresdk'

function App() {
  return (
    <ThemeProvider>
      <ToastProvider>
        <YourApp />
      </ToastProvider>
    </ThemeProvider>
  )
}

Theming#

ThemeProvider resolves the active theme ('dark' | 'light', default 'dark') onto <html data-theme="dark"|"light"> and exposes it through useTheme(). Every component reads its colours from the --color-*/--surface-*/--status-* custom properties in styles.css, so once the stylesheet and provider are mounted, components theme correctly with no further wiring.

const { theme, setTheme, commitTheme } = useTheme()
setTheme('light')     // paint only: a live preview
commitTheme('light')  // paint and remember the choice (localStorage 'theme')
Example useTheme()

Design contract#

DESIGN-CONTRACT.md says how an app built on stareSDK is laid out and which component to use for what. It is a contract, not a style suggestion. Read it before building a page. In short:

Rules that are never broken#

  1. Tokens only. Every colour, font, radius, shadow and spacing value comes from a var(--…) token (or chromeTheme.ts on render paths that cannot read CSS).
  2. Use the component that exists. One component per pattern. Don't hand-roll modals, badges, sliders, tab bars or panels.
  3. No unrequested controls. Never add a button, menu item, toggle or advisory copy nobody asked for.
  4. Icons are Tabler. Every icon comes from react-icons/tb.
  5. No placeholder states. Every view handles loading, empty and error explicitly, with real copy.
  6. Compositor-safe motion only. Animate transform, opacity and filter.
  7. Tight, not oversized. Components are compact by default; let tables and panels take the width.

Foundations#

Chrome colours come from two places, matched to where they are read. In CSS and inline style={{}}, use var(--token-name), resolved from :root (dark) and [data-theme="light"] in styles.css. On JS, Canvas and other non-DOM render paths, use chromeTheme.ts's DARK_THEME / LIGHT_THEME, or themeFor(name). Never call getComputedStyle from a render path. Each swatch below shows the live token in the current theme, with its dark and light values. Click a token name to copy var(--…).

Canonical roles#

The eight canonical token roles. Every surface, text run and accent in the system is one of these.

Surfaces, text and brand#

Status and links#

Status colours go through Badge colours success, warning, blue and danger. Links are always --color-link and underlined; the accent green is never a link.

Intelligence layer#

For charts, maps and overlays only, never for buttons or chrome. These are theme-invariant.

Badge fills#

BADGE_BG is one of the two deliberate raw-hex exceptions: Badge's contrastText() parses these as WCAG luminance values, so a var() string would not work.

Severity ramp#

chromeTheme.ts's severityRamp, for topology, map and HUD-style consumers, is the other raw-hex exception. Its hues stay distinct from the --status-* set.

Classification markings#

Domain colours, not chrome. They read the same in both themes, so a marking never changes with the reader's setting.

Typography#

Montserrat (--font-sans) for all chrome, Oswald (--font-header) for wordmarks only, and --font-mono for data values only.

Type scale

Spacing, radii and shadows#

Page padding --space-lg; gap between panels --space-md; between related controls --space-sm. Panels use --radius-lg, inputs and buttons --radius-sm/--radius-md.

Icons#

Every icon a stareSDK component renders comes from react-icons/tb (Tabler). Use the same set for anything you build around them. No other icon set, and no emoji or Unicode glyphs as affordances.

Reference#

Hardcoded-hex exceptions#

Two places in the package keep raw hex literals instead of var() references, mirroring the same two exceptions in OpenStare: badgeTokens.ts's BADGE_BG (parsed for WCAG contrast) and chromeTheme.ts's severityRamp. Map feature, track, tactical and data-viz colours inside OpenStare's layer rendering are deliberately theme-invariant and outside this package's scope.

Peer dependencies#

stareSDK declares its runtime dependencies as peerDependencies, so your app controls the installed versions: react, react-dom, react-icons, framer-motion, @dnd-kit/core, @dnd-kit/sortable, @dnd-kit/utilities, react-markdown, remark-gfm, mdast-util-find-and-replace, and mermaid (optional, loaded with a dynamic import() only when MDText renders a Mermaid block).

Lint#

The raw-colour-literal gate (eslint/colorLiteralGate.js) is exported for consuming apps, so colours stay on the tokens:

import { RAW_COLOR_LITERAL_SELECTORS } from '@kineticlogic/staresdk/eslint/colorLiteralGate.js'

export default [{ files: ['src/**/*.{ts,tsx}'], rules: { 'no-restricted-syntax': ['error', ...RAW_COLOR_LITERAL_SELECTORS] } }]

Development#

npm install --legacy-peer-deps
npm run check     # typecheck, lint (including the colour-literal gate) and tests
npm run build     # dist/
npm run docs      # this guide, into docs/

To release, bump version in package.json and publish a GitHub release tagged v<version>. The publish workflow then publishes the package to npm with provenance.
